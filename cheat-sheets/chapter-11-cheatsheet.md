## Chapter 11 Cheat Sheet — Process Redesign, Adoption & Scaling

### Adoption vs. Impact Metrics
| Category | Measures | Examples |
|---|---|---|
| Adoption | Is it being used? | Active usage rate, license utilization, prompt volume |
| Impact | Did the process improve? | Cycle-time reduction, cost savings, quality/error-rate improvement |

**Exam trap:** High adoption + flat impact = superficial usage. Never treat adoption as proof of value.

### Process Mapping Technique
Break the process into discrete steps, tag each:
- **Augment** — agent assists a human decision
- **Remove** — agent fully replaces the step
- **Unchanged** — needs human judgment/exception handling

Redesign should target Augment/Remove steps first.

### Baseline Rule
Capture baseline metrics **before** the pilot starts, using the *same* metrics you'll measure after (cycle time, cost, quality, volume). No baseline = no provable improvement.

### Iteration Loop (order matters)
1. Pilot
2. Gather feedback
3. Redesign process
4. Re-pilot to validate redesign
5. Decide: scale, iterate again, or stop

**Exam trap:** any option that scales before re-piloting a redesign, or scales on a single pilot cycle.

### Scaling Readiness Criteria
- Adoption AND impact metrics both improved vs. baseline
- Improvement sustained across re-pilot (not one-off)
- Support model and reinforcement plan defined for enterprise rollout

### Common Scaling Failure Modes
| Failure Mode | Symptom |
|---|---|
| Under-resourced support | Users hit errors, no clear escalation path, usage drops |
| No reinforcement | No manager check-ins/process reminders post-launch; users revert to old habits |

### Executive Reporting Checklist
- Adoption metrics vs. baseline
- Impact metrics vs. baseline
- Clear recommendation: continue / redesign / scale
- Avoid: raw logs, full feature lists, sentiment-only summaries

### Quick Memory Trick
"**A**doption = **A**re they using it. **I**mpact = **I**s it working." A pilot needs both to justify scaling.
